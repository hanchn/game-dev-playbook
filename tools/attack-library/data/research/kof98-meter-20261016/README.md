# 原版KOF98：自然气槽、DM与临界血SDM采集

范围是16名用户指定角色，官方MAME0.289，原ROM普通投币/菜单/方向/ABCD。所有内存、VRAM和palette只读；没有注气、改血、改时间、强制动作或训练模式写入。完整原screen/VRAM/palette/trace保留本机gitignored原始目录，源脚本与输入条件收据可复现。

## 实际失败→修复证据

1. 790Right、850Right或850Down都没有选到EXTRA：当时模式提示还没接受该切换，旧v1/v2/v3真实ADV画面已保留。B确认的v4也没成功。不能将ABC在ADV不充气称发动机失败。
2. 已实看有效时序：初期P1不按900的A；960..964按Down；1020..1022按A确认；1080图显示绿色EX。角色方向路由从1080按12帧节奏走，1230/1320/1410按A选3人；1500之后按原A确认顺序。P2按原ADV路径。旧790/850/900失败版没有删除。
3. EXTRA战斗中按住P1 ABC，实际meter raw0→99→160，原画面出现MAXIMUM。蓄气后释放再静置，不能边蓄气直接猜出招已生效。新队列使用自然充气240帧、放开/站稳36帧；这是实验输入设置，不是恢复的原引擎最短窗口。
4. 单纯236236连续方向在本次输入采样时只得到普通拳/近身动作，Kyo/Benimaru/Joe旧版实际contact及未耗气证据保留。改为236→中立3帧→236才实际见无式黑闪、火柱/连击和雷光拳雷球。该中立帧是本次普通I/O采样修复，不称游戏命令表硬性要求或唯一出法。
5. P2普通A逐次实际击中使P1血量103→19/21，再充满气，仍只出现蓝闪普通DM。不能仅因看着低血就把它标MAX。进一步自然打到9，Benimaru出现橙闪、黑场金橙雷球和更多连击，C指令也由DM对空雷光变为横向SDM，符合原作者Kao_Megura的原版描述。9是已实测可用采集目标，不声称临界阈值恰好等于9（只证19不够、9已足）。旧19/21批均保留条件差异。

## 输入、状态与产物边界

- 官方部分表：36个超必杀按钮变体，正常/自然低血两种条件共72对局候选。新版本neutral-v4补完整320观察帧；更早160观察帧可能只覆盖长连击前段，不称完整动作结束。
- `author-dm-queue.json` 扩展至原作者表74个具名基础DM按钮/空中候选，含官方未列的第二/第三DM。16人完整表仍需Daimon连续投链、Athena晶体球派生与取消、长按释放、命中/空振等专门序列，不能将74或148当“全部动作已通过”。
- `playback-index.json` 仅拼实际连续screen图，sourceTick与ticks保留。捕获/满足气血/触发/角色身份/MAX视觉差异各自记录。新批默认not_verified，只有实际view过才observed。自然条件完整但出招失败保留not_observed。
- `trace.csv` 全段实际screenFrame必须每行+1，源脚本callback有全局门闩。长自然充气/损血过程每10帧留原screen用于条件观察，不能把它们假称逐帧全量动画；实际动作窗口逐帧原screen+VRAM+palette。
- 59.185606Hz来自实际MAME0.289 `mame kof98 -listxml` display字段。采集运行nothrottle的wall-clock加速不改变原游戏刷新时间。

只读气槽地址来源：固定peon2原版profile `bf3541e1d4f586f76f401617af4fa842447591de/games/kof98/kof98.lua`，实际下载SHA见source-receipts。该原训练脚本含写血/气/时间，作为原件研究保存但没有执行，采集Lua只read_u8/read_i16读取0x1081E8/0x108239等。stock/timer raw没有单独验证为模式真值，以原画面和实际触发佐证。

中止旧v2队列时，MAME将SIGTERM当正常退出，Python父队列曾继续，随后明确结束自己的旧runner。缺condition-result的中断批不自动归入完整动作；其他人的MAME进程未停止。
