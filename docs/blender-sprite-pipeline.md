# Codex + Blender + Sprite Sheet 标准化制作流水线

状态：2026-10-15，用户已选定的生产路线；首轮实际 Blender 导出试验已运行，角色美术与街霸动作还原尚未验收。这里保存方法和边界，自有角色图片、模型及可编辑工程只放私有游戏仓库。

## 分工与交付物

生产顺序：角色设计母版 → Blender 模型、骨架与动作 → 固定镜头透明 PNG 序列 → 图集和播放元数据 → Phaser 游戏实播。

- Codex：维护动作需求、角色字典、批处理配置、导出脚本、校验、引擎接入及版本记录。
- Blender：建立可复用的角色母版，制作姿势和表情，用同一套渲染条件输出完整角色帧。
- Sprite Sheet：只是输出资源格式；必须同时携带帧位置、锚点、播放时长、循环及来源信息。
- Phaser：播放二维图片，执行输入、位移、命中、防御、击倒、回合与音画反馈。运行时不需要 Blender 或三维模型。

相比逐张生成独立图片，这条路线能减少脸型、体型、服装、光照和机位在动作之间漂移。效率主要来自母版和动作工程的复用；模型、权重或关键姿势错误，也会一致地导出错误。不能用“统一流水线”替代美术判断。

## 母版先验收，再批量

先以用户最终确认的设计图锁定脸、眼睛、嘴、服装、体型及四肢比例。检查正面、侧面、三分之四视角，以及游戏内约两百像素高度时的辨识度。旧模型只有在通过身份和比例复核后才成为生产母版。

每种体型需要合适的关节与权重。人形、梨形短腿角色、带尾角色、鸟和鱼可以共享动作命名与导出契约，不代表都能使用同一套骨骼或原样重定向。握拳、接缝、肩肘膝弯曲和极端姿势需要实际检查。

首个代表样本至少包含待机、格斗步、出拳起手/接触/收招、受击及倒地中的一组。代表样本未通过，不向其余角色复制失败方法。

## 固定渲染条件

同一个角色动作集锁定以下参数，并保存为版本化配置：

| 项目 | 固定规则 |
| --- | --- |
| 镜头 | 正交相机、相同机位/朝向/正交尺寸；不逐帧自动对焦或缩放 |
| 世界尺度 | 统一单位和地面；允许角色本来高矮不同，禁止逐帧按包围盒等高 |
| 画布 | 固定宽高、透明 RGBA、有足够边距容纳拳脚与倒地 |
| 锚点 | 把同一个世界地面基准投影到画布；保留浮点锚点和全部透明边距 |
| 材质与光照 | 同一套版本化材质风格、灯光、色彩管理、阴影和轮廓规则 |
| 动作时序 | 区分源动作时间、图像采样次数和游戏逻辑 tick；不能一律等时播放 |
| 朝向 | 记录真正渲染方向；非对称服装和持物不能默认镜像就正确 |

固定机位能保证导出一致，但不能保证渲染结果自动呈现经典手绘街霸风。需要单独审查轮廓、色块、材质、关键姿势，以及必要的二维修绘。透明 PNG 仍须在深浅两种背景检查边缘。

## 动作契约

基础动作包含待机、前进/后退、蹲、跳、落地、防御、受击、击倒、起身、KO、胜利和失败。普通技按站立/蹲下/空中与轻中重拳脚分槽；每个角色的特殊技、大招和投技分别制定关键姿势与接触时刻。

每个角色还需要独立的嘲讽、挑衅、欢呼、臭美、生气、悲伤动作。缺失项标为 pending，不能把同一段动作重命名后当作已完成。

源工程的 `light1` 只是一个源动作名，不能因为字面接近就宣称是街霸的轻拳；`super` 也不能自动当作某个指定大招。对标关系、接触帧和受击反应需要逐项核验。经典街霸光栅帧研究并不提供可恢复的原始骨架，重建骨架和重定向必须明确标注。

## 可执行导出与检查

使用固定版本的 Blender，以后台命令执行脚本。启动参数应明确指定 Python 异常退出码，不能只依靠控制台最后出现图片文件名判断成功。官方说明见 [Blender 命令行参数](https://docs.blender.org/manual/en/4.2/advanced/command_line/arguments.html)。

推荐分为四个可单独运行的步骤：

1. **Inspect**：记录模型 SHA、真实骨骼、网格、形态键、动画通道、动作名和时长。静态模型没有动作时就停止该动作的导出。
2. **Render**：保留源文件不变，在派生工程里配置镜头。按确切源动作名启用全部相关骨骼及形态键动画，输出完整 RGBA 帧；记录源帧和播放 tick。
3. **Pack / Validate**：无缩放地拼图，输出 Phaser atlas 与动作清单。检查空帧、触边裁切、尺寸/锚点不一致、源文件哈希和实际不同帧数。技术打包不修改角色像素。
4. **Engine QA**：实际引擎慢放、逐帧、正常速度检查循环、脚滑、轮廓、四肢连续性、攻击接触、命中停顿、倒地/起身和左右朝向。保存真实截图或录屏。

图集透明裁边如确有必要，必须携带原始画布尺寸、偏移与锚点；不能逐帧居中后丢失作者坐标。首版优先保持完整格，降低错误风险。输出写入全新版本目录，拒绝默默覆盖上一版。

## 首轮实测与失败边界

已在 Apple Silicon 本机使用 Blender 4.5.3 LTS，真实导入一个自有旧角色 GLB。导入后检查到 47 根骨骼、4 个动画拥有者，包含 25 个源动作；待机、走路和一段源出拳分别导出 12 帧，总计 36 张 512×512 透明 PNG。

试验固定正交尺寸 3.5、60Hz 源时间轴和投影地面锚点，三个动作不逐帧缩放或重定位。保留派生 `.blend`、源文件哈希、逐帧源时间与播放时长。这证明后台导出链路能运行，**没有证明旧角色设计或旧动作合格**。

实际看图发现旧模型仍是肌肉化体型，与新参考要求的柔软梨形身体、闭嘴面部不符。不能把旧模型重新渲染后直接放回游戏，并宣称形象问题已经解决。接下来先修正或重建母版，再使用同一导出配置验证；不能继续扩大错误母版的产量。

## Epic 验收顺序

母版与渲染风格 → 一组完整动作 → 单角色游戏接入 → 全角色与独有招式 → 表情和场景演出。每个阶段都执行“实现 → 对应测试 → 保存实际画面和失败 → 知识沉淀 → 提交推送”。

分别记录技术通过、引擎接入、视觉验收和用户认可，不用脚本通过或帧数增加替代后两项。
