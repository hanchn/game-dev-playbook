## 2. 先固定玩法合同，持续修订而不让旧规则混入新规则

这个游戏的循环是：探索 → 入池舀水 → 运水 → 向着火物体倒水 → 保留灭火进度 → 扑灭计分 → 继续探索。需求不能停留在“有水、有火、有动物”的名词列表，必须落到条件和状态转换。

| 对象/交互 | 最新约定 | 被覆盖的早期方案 |
| --- | --- | --- |
| 舀水 | 进入水塘、落脚池底后俯身舀水；水量有限、延迟恢复 | 在岸边范围内直接吸水 |
| 池内倒水 | 桶水回灌原池，不溢出、不加灭火分，平息鳄鱼 | 在池里也作为普通灭火消耗 |
| 灭火 | 对朝向内的着火物体生效，大火多次取水；从正火势变零加一分 | 一桶必灭或按倒水次数计分 |
| 鳄鱼 | 仅舀水抽干那刻站起挥拳一次；雨天不攻击，回灌取消攻击 | 任何取水持续触发追咬 |
| 干池生物 | 最后一次挥拳结束后鱼鳄隐藏，回水恢复 | 干池鱼继续蹦跳 |
| 蛇 | 地面踩到才反应；树蛇有独立的盘绕、落地、爬树和咬鸟节奏 | 主动追人或接触范围过宽 |
| 跳跃 | 支持二段跳、第三次无效，落地/洞顶/复活重置 | 仅单跳，坑宽与可达距离不匹配 |
| 洞穴 | 顶部可落脚、站立躲地面蛇，走出后落下 | 单纯装饰贴图 |
| 深坑 | 整个角色下落、缩小、消失，扣命后回边缘 | 立刻传送或硬裁掉角色 |
| 地貌/天气 | 无限左右地图、草地/砂石地/沼泽/森林，雨补水并削弱大火 | 同一地面换标签，昼夜只调亮度 |

通用做法：每次用户修订同时更新触发、例外、中断、资源收支、显示和回归用例。保留旧方案为历史，不让旧分支继续参与当前判定。项目早期文档中仍有旧术语、参数和骨架描述；复用时应以固定提交的最新模型与明确修订为准，不能直接抄整篇旧说明。

## 3. 开发架构：规则只有一个来源

| 责任 | 本项目入口 | 可复用的边界 |
| --- | --- | --- |
| 规则与世界 | `src/model.mjs` | 只管理数据、输入、时间和事件，不引用 DOM/Phaser |
| 镜头与基础参数 | `src/config.mjs` | 世界坐标与屏幕坐标换算集中，喷口位置共享 |
| 场景组合/输入/HUD | `src/app.mjs` | 引擎读模型，按键只发语义动作，不直接扣水加分 |
| 绘制 | `src/renderer.mjs`、`src/parallax.mjs` | 从状态推导画面，不在 draw 内结算伤害或恢复水量 |
| 角色动作适配 | `src/characters.mjs` | 图集帧、朝向、脚点与动作相位独立于物理推进 |
| 首次进入 | `src/bootstrap.mjs` | 首页、点击后加载、失败与首帧就绪边界 |
| 反馈 | `src/feedback.mjs` | 消息队列、优先级、受击闪屏与浮动扣心 |
| 资源元数据 | `data/*.json`、`scripts/calibrate-sheets.mjs` | 源尺寸、帧格、脚点候选、来源和哈希 |

具体源码入口见 [来源索引](dinosaur-firefighter-evidence/source-index.json)。这套拆分的价值是：改鳄鱼图集不改变抽干规则，改按钮不改变跳跃次数，改池塘比例时只需明确更新共享几何，而不是让渲染器偷偷造一个新水面。

当前状态为 `menu/loading/playing/paused/over` 的组合入口：DOM 负责最初首页与加载，Phaser 管后续首页/局内/暂停/结束。模型只在 playing 推进；失焦清输入并暂停，delta 有上限。复用时还要单独检查 UI Tween、消息计时器和相机效果的暂停/清理，模型冻结不能证明所有引擎计时器都冻结。`GameFeedback.clear()` 已有接口，场景切换是否完整接入仍需要核查。

## 4. 美术设计：身份、尺度和操作语义要同时成立

最初背景和木框细节很多，但角色瘦腿、帽靴另贴、嘴形错位、动物大小失衡、按钮图标误导，整张画面仍被拒收。堆叠精致单件不能代替整体设计。

可复用生产顺序：

1. 锁定用户认可的主角身份：头身比例、肉感腿、脸型、嘴、帽子、背心、雨靴、桶及朝向；保存参考源图。
2. 在实际游戏显示尺寸中，摆一只主角、一幢房屋、一棵树、一口池塘和一只鳄鱼，先确定比例关系及可读性。
3. 为首页、HUD、方向盘、动作键、加载、消息和结算分别分配功能与图槽，出专用源件；不能拿按钮壳代替救援计分牌。
4. 先接一条完整循环和动作，再扩充动物、天气及装饰。用户看到的运行版比资产目录中的候选数量更重要。

“可爱”必须变成可观察的形体，不可只写在 prompt 里。完整角色帧可以解决旧骨架与新形象冲突，但仍需检查跨动作的头部大小、躯干厚度、手脚身份和道具位置。当前完整帧已接入，不能据此宣称所有动作自然。

## 5. 动作设计：画面动作和资源结算共用一份合同

动作应至少写清：起始条件、准备姿势、生效点、持续状态、恢复、失败、中断。动作表和实际渲染的细节见 [动作指南](../action-semantics.md)。

本项目关键教训：舀水要俯身、桶口进入水中；倒水的桶口朝外，不朝嘴。新倾桶 PNG 已含水流时必须删除旧曲线，不能重复画两条水。挥拳前要有站起与蓄势，拳头到位才扣命，站位不能让鳄鱼整个藏在恐龙身后。池底与靴底需在同一几何中，不能用漂浮偏移掩盖碰撞不匹配。

复用已有库要先检查形体是否适配。本项目蛇继续使用 flex-rig，恐龙、鳄鱼、鹿等改全身动画图；“复用运动库”不表示把错误比例永久保留。当前 jump 仍复用跑动帧，不是专门新作的腾空姿势；四帧也不代表每种动作都已经足够流畅。

## 6. 无限场景：先共享几何，再安排装饰

世界由有限驻留区块生成，当前每块2400单位、最多5块；远块回收后重访会重新生成，没有永久世界保存。这里的可复用模式是“预算与生成分离”，不是固定照抄5块。

地面坡度、池水面、池底、泥洼、建筑底边、洞顶、NPC通行区、危险触发半径和美术占地应分开命名，但从同一几何定义派生。按完整画面宽度预留布局空间，不仅比较中心点；洞旁泥地和兜底深坑必须参加最终布局检验，不能在检验后随手追加。

树林、天空和土层的首尾接缝需要在镜头向左、向右及跨区块时查看。运行时窄幅渐混仅是补偿方式，会有重影或色调变化风险，不等于源图天然无缝。火山最新修正采用整体放大并位于所有树林/地面之后，以喷口为锚，避免完整山脚露出；参数和遮挡说明见 [场景指南](../side-scroller-composition.md)。

## 7. 资源循环、敌人和天气是相互影响的状态系统

| 状态转移 | 需要一起更新的内容 | 有效断言 |
| --- | --- | --- |
| 池水正值 → 舀空 | 恢复时间、最后取水量、鳄鱼 armed/拳击事件、鱼显隐 | 只触发一次；持续按键不重复发起攻击 |
| 回灌 | 桶水、池水、容量上限、恢复计时、鳄鱼平息 | 桶池收支对应，满池不继续扣水，不加灭火分 |
| 下雨 | 补水、鳄鱼安静、大火转小火 | 天气逻辑改变规则而不只叠雨线 |
| 火星落地 | 目标可燃物 ID、火势、独立玩家伤害 | 到达后才点燃；生成时不能直接着火 |
| 火势正值 → 零 | 分数、完成反馈、后续火势 | 一处一次计分，剩余水不为负 |
| 掉坑/拳击/蛇/陨石 | 统一 hurt、保护期、消息、扣心、终态 | 一次受击不按帧反复扣命，耗尽后停止本帧后续结算 |

“水被抽空后移除鱼鳄”与“抽空触发挥拳”不能分别写成互相覆盖的 if；应先允许最后一次动作完成，再进入隐藏状态。反之，回灌或雨天又可中断攻击。业务边界比动画资源名更稳定。

## 8. NPC 生态：控制原因、节奏与可行路径

兔鹿卡死并非一定是运行卡顿：若每帧发现池岸就翻转，已在禁区内部的动物会左右震荡。先建立可通行区间，在足够宽的区间出生，遇边停留再转身；布局给不出足够空间时要明确不生成、休息或换位置，不能让它反复撞墙。

鸟的飞行需要原因和落点：避开燃烧树、按距离给飞行时长、抵达后稳定停栖。树蛇咬鸟必须有独立冷却，不能每只鸟落下就重新赶走。世界时钟、动物状态年龄和步态时钟分开；停步状态不要仍飞快蹬腿。偶发行为不能代替基础循环的可靠性。

## 9. UI、加载和输入：以用户可见结果收尾

在首页点击开始才加载引擎和场景；完成需包括资源、纹理和首帧。进度从真实阶段推导，跑动角色可以按计时器播放，但不能用它的跑动时长伪造加载百分比。弯曲进度槽用原图内部遮罩，HUD 按原始槽坐标映射，不能凭整个 PNG 的透明外框猜偏移。

四向盘是一张整体十字图，四个独立热区，键盘与每根触摸指针分别持有状态。一次松手只释放自身输入。按一次触发的跳跃和持续按住的取/倒水必须分开处理。

受击、空桶、入池要求及池满使用公共消息组件；模型发事件，界面排队、去重和处理优先级。旧淡出 Tween 不能把新提示提前隐藏。改变新素材后需确认用户那一页是否仍载旧资源；版本文件名和实际刷新是交付链路的一部分，详见 [UI指南](../ui/art-runtime-integration.md)。

## 10. 验证、来源和交付

| 证据 | 能说明 | 不能说明 |
| --- | --- | --- |
| PNG尺寸、alpha、SHA256、帧矩形 | 文件身份、导入边界和透明安全线索 | 脸像设计稿、动作自然 |
| 31条历史模型回归 | 指定版本中的规则结果与边界 | 完整动画、触控实机、所有天气画面 |
| 浏览器单次截图与日志 | 对应时刻的布局、加载/错误状态 | 连续循环自然、长期性能 |
| 用户原话与拒收图 | 对应问题和明确偏好 | 所有后续版本自动认可 |
| 推送成功 | 代码或文档进入指定远程分支 | 已部署、正在运行、用户能在线玩 |

项目的素材回执、帧校准和资源SHA256均保留在游戏仓库；本知识库保存摘要与稳定版本链接，不重复搬运整套运行素材。旧自动校准会按2×2切帧、用颜色启发式估靴子中心，这只是该批资源的工具，不能不核对就用于任意图集；人工覆盖和特定锚点不应被脚本重跑覆盖。

并行出图曾因 `Promise.all` 中一个拒绝导致编排结束、其他尚未完成的任务结果丢失，后改为 `Promise.allSettled`，逐项保存回执并检查结果。并行制作要明确文件归属及共享的水面/池底/平台几何；分工不能消除最终整合的责任。

发布收尾顺序是：保存源码与来源 → 按授权执行检查 → 记录未通过项 → 提交/推送并处理冲突 → 按用户要求关闭服务。不要用“已推送”替代“已部署”，不要为文档沉淀擅自恢复已关闭的游戏服务。

## 12. 仍未证明的部分

本案例尚未完整获得用户美术认可。新挥拳站距、池内倾桶、深坑缩隐、洞顶支撑及最新火山比例需要在正常游戏里连续观察；头身跨动作一致性、蛇帽子/蝴蝶结、鸟蛇交互以及各种屏幕上的控件/前景遮挡仍不能靠31项模型测试签收。音效、永久世界保存和广泛移动设备性能没有本次完成证据。复用上述方法时，不能把这些缺口包装成成熟资产或已验收能力。
