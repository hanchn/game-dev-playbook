# 街霸式纯2D游戏：Epic实现、测试与知识沉淀

记录日期：2026-10-15。此记录覆盖已做过的试验与检查，不代表游戏完工、全部角色完成或原作一致性验证完成。私有游戏工程为 `hanchn/street-fighter-naifrog-2d`；外部资料与解码工具在本经验仓库的 `tools/attack-library`。

## 1. 每个Epic的关闭条件

按“实现 → 测试 → 沉淀方法和失败案例 → 提交 → 推送 → 关闭”推进。先写功能验收项、依赖和不在该Epic内的部分，避免把完整游戏拆成数个各自声称完成、合起来却无法玩的组件。允许关闭明确的功能底座子批次，但父Epic和全游戏仍按实际缺口保持进行中。

至少记录：变更文件、复现输入、预期行为、实际输出、规则测试、引擎/浏览器观察、截图位置、原作对照状态、未覆盖条件、提交与远程推送结果。下载、CRC匹配、可解码、可播放、规则相符和用户美术认可是不同层次。

## 2. 选型纠偏：正式运行时使用Phaser

本轮早期为了复用旧工程与验证模型烘焙，使用Godot试验。用户要求的是自有角色的纯2D街霸式游戏，继续把3D烘焙接入画面偏离了目标。修正方式是将新增Godot试验归档到 `experiments/godot-2026-10-15`，正式入口改为Phaser，禁止引用原3D模型和烘焙角色帧。

Phaser本身提供浏览器2D渲染、场景、输入与资源加载能力，见[官方框架说明](https://docs.phaser.io/)和[输入文档](https://docs.phaser.io/phaser/concepts/input)。格斗规则保持独立固定步长状态机，渲染只消费状态与事件，不把普通物理碰撞回调直接当作完整格斗判定。

正式工程使用 `src/core/input.mjs`、`fighter.mjs`、`match.mjs` 与Phaser场景分离。旧规则可以作为行为测试来源，不能因曾通过测试就把旧美术、旧招式和旧时序保留为最终实现。

另有资源准入测试：正式 `src` 与 `public` 不引用旧3D烘焙或模型；角色字典与名单名字一致，每个身份具有独立参考、背景和大招规划。未实现的非隆系角色不能自动获得一套通用波动拳。

## 4. 从原作姿势到自有角色出图

固定版本、角色、动作与条件；原作和MUGEN改编分开。先保存源帧、画布宽高、透明边、轴心、偏移、停留时间、关节/躯干方向、重心、支撑脚与接触点，再生产自有角色帧。无原始骨骼时，关节标注属于重建，不叫恢复了原版骨架。

画风研究包括轮廓、头身、线条、色阶、光源、遮挡、像素密度和动作夸张；制作工艺只有工程或可靠资料能证明。[CPSS](https://github.com/fabiensanglard/cpss)提供图块与调色板重建研究，不能当作动画脚本、原始rig或完整制作工程。对应原作访谈链接本轮返回403，未直接验证的工艺描述保持未知。

单帧原生尺寸不能被图集方格取代。当前改编包495帧几何审计见 `data/research/sf-frame-geometry.json`；它不等于原作规范。社区隆精灵表也包含多版本/调色板，表内摆放和背景色不是原生画布、轴心或时序。

源动作可能复用少数姿势并用不同停留时长表现节奏。不能为了凑8帧发明原作不存在的过渡，也不能把几十个几乎相同的格子算成丰富动作。必须同时看源姿势差异、帧序、时间和实际动作完整度。

## 5. 失败候选与误区

- 整页AI图集：本轮请求8×12格、2048×3072，实际产物1024×1536，格网/轴心和动作连续性不可靠，且未锁定源姿势；有低透明度边缘背景。已保存为拒收候选及提示词，禁止接入。生成成功不等于资源可用。
- 3D转2D：用户不接受的比例、肌肉、脸型和姿势不会因导出PNG而自动变正确。正式纯2D路线禁止继续复用这批烘焙。
- 动作标签：六个按钮或六个不同动作ID不等于六套独立拳脚动画；后者仍需源帧对照与美术制作。
- AIR/CNS：等待帧、物理与状态切换必须一起研究；直接用通用计时器播放会造成空中停滞和突然倒地。
- source代码也需核对：CPSS源码中部分地址有不确定注释，两个末尾code bank基址重复，未经映射验证不应盲信输出。
- UI信息：尚未实现的巡回赛关卡不能写成“赢两局自动下一场”；本批只验证单场两胜、结果和重赛。

## 6. 角色/招式字典与背景设定方法

每个独立角色建立稳定ID、正式名、换装列表、固定参考版本/角色、战斗定位、对标理由、普通技语义槽、特殊技/投技/必杀/大招、输入与条件、源帧/几何/时序、判定/位移、消耗/取消、特效音效事件及验收状态。缺少证据的数值使用null，不填写看起来像真的帧数。

普通技语义槽是覆盖检查，不是独立素材数量。参考角色存在按键例外、共享姿势或近远距离分支时明确记录，不强行给拳击手补普通踢腿。角色背景包含身份、经历、动机、性格、关系、主场、出场和胜利台词；原创设定草案与原作事实分开。私有角色字典/背景保留在私有游戏仓库。

## 9. 原版 SSF2T 双人采样：E03a

旧 Kawaks 包缺密钥的结论只适用于该旧包。本批另外保存 `assets/original-games/mame-0289/` 三个完整包，保留旧包与原 SHA。MAME 0.289 对 sf2ce、ssf2t 输出 `2 romsets found, 2 were OK.`；SSF2T 实际进入双人战斗，不能继续把“原版不能运行”当成当前状态。下载来源、成员 CRC、包 SHA 与运行状态见 `tools/attack-library/data/research/mame-0289-packages.json`。

原版采样只通过 Lua I/O 插币、加入双人、确认人物并输入动作；不修改游戏内存。双人隆对肯避免 CPU 自动行动干扰。逐屏幕帧只读记录游戏状态、动画指针、位置、血量、hitfreeze、输入、镜头与原始计数值；按动画指针/状态改变或15屏幕帧保存原生384×224视口。MAME `-listxml` 显示原始刷新率59.637405Hz，不能把所有原作时序一律叫60Hz逻辑帧。

已验证：待机、远距离站立六键、蹲下六键、垂直跳跃六键，轻波动拳/轻升龙拳/轻旋风腿；另有近身六键受击与KO采样。motions 2112行/691截图，contact 1248行/397截图，合计3360行/1088截图。波动拳阶段对方血量144→128；近身受击观测到state14与hitfreeze计数，最终血量字段65535并出现KO飞出画面。不能把某次掉血、计数最大值或一段状态的长度写成通用伤害/硬直/启动帧规范。

复现（Python需Pillow，MAME需0.289及已核验ROM）：

```sh
python3 tools/attack-library/scripts/run-ssf2t-study.py --output output/attack-library/mame-study/new-run
```

输出目录拒绝覆盖已有trace。`package-ssf2t-study.py` 检查22个动作阶段、回合未跨界、六键进入普通攻击状态、空中高度改变、三种轻特殊技进入special状态、受击/hitfreeze/KO证据，并保存原始截图/CSV ZIP与无损视口图集。报告含脚本与产物SHA。库内 `original-study.html` 实际验证了动作选择、播放/暂停、采样拖动、框线开关、近身组切换和KO血量显示，浏览器错误日志为空。

研究框线只读移植自 [sf2-hitbox-extractor](https://github.com/JordanAnthonyKing/sf2-hitbox-extractor/tree/cf65fd8da487affce4b68788c56e0ea3667ed721)，原作者Dammit、MZ、Felineki；保留push/hurt/attack指针原值及重建屏幕坐标，未移植会写内存的throw清零代码。尚未校准原版渲染延迟，也未验证投技/飞行道具框，因此开关明确标“研究判定框”，不能当作已完全还原的碰撞系统。重建原点不是恢复出的美术制作轴心。

失败与修正：

- 单次一屏幕帧投币/开始在本轮初始化序列未进入对战；多帧脉冲与实际双人画面共同验证后才采用。
- MAME官方Lua文档中的frame_number在当前运行时是方法；兼容方法/属性，避免格式化函数对象导致每帧报错。
- 首次120屏幕帧动作间隔导致末尾旋风腿落在TIME OVER，拒绝作为成功样本。改96间隔重跑，所有motions记录gameState=10，旋风腿进入state12。
- KO血量读取为65535，不能当“血量极高”；查看原始值与KO画面再解释。KO时state0也不能单独说明角色回到正常待机。
- 将只读观察与采样查看器保留在资源库，不把原版视口/改编角色混进奶蛙正式美术。未采样的画面通过最近样本保持，播放不是完整录像。

下一关仍是原生角色画布/透明边/轴心、动作与判定时序精确关联、其余角色及大招、纯2D自有角色生产。当前原版运行成功不代表这些条件已满足。

## 10. 透明原版角色帧与真实图块画布：E03b

本批从MAME已解码gfx region、原版调色板和锁存渲染对象列表重建RGBA。依据 [MAME 0.289 CPS2渲染器](https://github.com/mamedev/mame/blob/mame0289/src/mame/capcom/cps2.cpp) 与 [16×16布局](https://github.com/mamedev/mame/blob/mame0289/src/mame/capcom/cps1.cpp)，按图块码、组合行列、翻转、对象偏移和色号拼接；透明来自pen15，而非按黑色抠图。全程只读ROM/RAM/模拟器渲染保存项，不修改游戏或调色板。

先用单帧验证：隆3176个不透明像素全部与原始截图一致。批量直接读取两块对象RAM会因缓冲时序错位，许多空中姿势校验失败；改为通过 `manager.machine.devices[':'].items['0/m_cps2_buffered_obj']` 定位保存项，使用 `emu.item(index):read(wordIndex)` 读取实际锁存渲染对象。保存项索引不能硬编码为131：版本可变，要按名字解析并校验元素宽度2字节。其接口通过同版本 `src/frontend/mame/luaengine.cpp` 核对。

当前严格通过1287条角色帧观察：隆678条、62个不同RGBA姿势；肯609条、4个待机姿势。95条未通过逐像素核验的观察单独保留拒收记录，不放宽阈值凑数。每条接受记录的不透明可见像素100%匹配原截图，采用真实锁存buffer（bank0），没有视口裁切。66个不同RGBA按图像去重打包，1287条引用仍保留各自时间、对象位置和元数据；逐项裁回图集校验RGBA SHA，不把重复观察报成1287套动作。

隆的实际渲染图块画布宽64–160、高64–128，取决于姿势；保留每帧图块画布、可见alpha边界、屏幕位置及RAM投影原点。例：最初待机为64×96组合图块画布。它是原版渲染对象的组合范围，不是Capcom原始绘制文件画布。RAM原点投影也不是恢复出的美术轴心，渲染到RAM的帧差仍未校准。

复现：需MAME 0.289、Pillow、NumPy及已核验包，运行 `python3 tools/attack-library/scripts/run-ssf2t-study.py --output output/attack-library/mame-study/new-native-run --native`。完整封装已实际跑通并重现相同计数与完全一致的图集SHA。gfx region可以由原ROM和脚本重建，未重复归档16MB的region；保存其SHA与所需原始对象/调色板CSV。查看器增加透明帧开关，缺少严格验证的采样明确提示，而不替换成别的姿势。

两个工具误区：Lua `dofile` 的环境使外层脚本全局回调未被子脚本看到，首批只得到CSV表头；改用 `loadfile(actions)(capture)` 显式传闭包。系统Python不带Pillow，素材工具使用已提供的工作区Python；不要把错误解释成解码失败。

本批透明图块进入外部研究库，没有成为奶蛙正式角色。后续需要完整密集逐帧捕获、动作/判定/时间关联、自有角色按源姿势生产，以及其余参考人物与大招。
