# 街霸式纯2D游戏：Epic实现、测试与知识沉淀

记录日期：2026-10-15。此记录覆盖已做过的试验与检查，不代表游戏完工、全部角色完成或原作一致性验证完成。私有游戏工程为 `hanchn/street-fighter-naifrog-2d`；外部资料与解码工具在本经验仓库的 `tools/attack-library`。

## 1. 每个Epic的关闭条件

按“实现 → 测试 → 沉淀方法和失败案例 → 提交 → 推送 → 关闭”推进。先写功能验收项、依赖和不在该Epic内的部分，避免把完整游戏拆成数个各自声称完成、合起来却无法玩的组件。允许关闭明确的功能底座子批次，但父Epic和全游戏仍按实际缺口保持进行中。

至少记录：变更文件、复现输入、预期行为、实际输出、规则测试、引擎/浏览器观察、截图位置、原作对照状态、未覆盖条件、提交与远程推送结果。下载、CRC匹配、可解码、可播放、规则相符和用户美术认可是不同层次。

## 2. 选型纠偏：正式运行时使用Phaser

本轮早期为了复用旧工程与验证模型烘焙，使用Godot试验。用户要求的是自有角色的纯2D街霸式游戏，继续把3D烘焙接入画面偏离了目标。修正方式是将新增Godot试验归档到 `experiments/godot-2026-10-15`，正式入口改为Phaser，禁止引用原3D模型和烘焙角色帧。

Phaser本身提供浏览器2D渲染、场景、输入与资源加载能力，见[官方框架说明](https://docs.phaser.io/)和[输入文档](https://docs.phaser.io/phaser/concepts/input)。格斗规则保持独立固定步长状态机，渲染只消费状态与事件，不把普通物理碰撞回调直接当作完整格斗判定。

正式工程使用 `src/core/input.mjs`、`fighter.mjs`、`match.mjs` 与Phaser场景分离。旧规则可以作为行为测试来源，不能因曾通过测试就把旧美术、旧招式和旧时序保留为最终实现。

## 3. 当前功能批次的验证证据

Phaser 3.90.0 / Vite 7.1.12，`npm test` 当前15项通过，`npm run build`通过；约1.7MB压缩前JavaScript包含Phaser，仍有大包提示。测试覆盖：左右朝向输入、六键边沿、波动/升龙/双波动优先级、过期输入、独立拳脚动作ID、连续跳跃、高低防御、普通技无削血、投技不被格挡、气槽单次扣除、KO落地停留、起手无伤害、单招单次接触、hitstop期间计时不流失、同时命中互换伤害、两胜回合、超时与AI正常输入跑到结果。

另有资源准入测试：正式 `src` 与 `public` 不引用旧3D烘焙或模型；角色字典与名单名字一致，每个身份具有独立参考、背景和大招规划。未实现的非隆系角色不能自动获得一套通用波动拳。

浏览器实测：菜单/模式/双方确认/场景选择/判定模型对战；暂停和招式表；重复按键拦截；改键刷新后持久化并恢复默认；比赛实际结束为0:2；重赛恢复第1回合及0:0比分；检查的两个标签页错误日志为空。截图与报告在私有工程 `output/qa/phaser-*.png`、`data/epic-e02-verification.json`。

这不是角色动画或原作帧数据验证：规则验收入口只显示明确标注的判定模型。正式入口在纯2D角色动作未就绪时保持关闭，不能用旧3D素材或静态头像冒充完成角色。

## 4. 从原作姿势到自有角色出图

固定版本、角色、动作与条件；原作和MUGEN改编分开。先保存源帧、画布宽高、透明边、轴心、偏移、停留时间、关节/躯干方向、重心、支撑脚与接触点，再生产自有角色帧。无原始骨骼时，关节标注属于重建，不叫恢复了原版骨架。

画风研究包括轮廓、头身、线条、色阶、光源、遮挡、像素密度和动作夸张；制作工艺只有工程或可靠资料能证明。[CPSS](https://github.com/fabiensanglard/cpss)提供图块与调色板重建研究，不能当作动画脚本、原始rig或完整制作工程。对应原作访谈链接本轮返回403，未直接验证的工艺描述保持未知。

单帧原生尺寸不能被图集方格取代。当前改编包495帧几何审计见 `data/research/sf-frame-geometry.json`；它不等于原作规范。社区隆精灵表也包含多版本/调色板，表内摆放和背景色不是原生画布、轴心或时序。

源动作可能复用少数姿势并用不同停留时长表现节奏。不能为了凑8帧发明原作不存在的过渡，也不能把几十个几乎相同的格子算成丰富动作。必须同时看源姿势差异、帧序、时间和实际动作完整度。

## 5. 失败候选与误区

- 整页AI图集：本轮请求8×12格、2048×3072，实际产物1024×1536，格网/轴心和动作连续性不可靠，且未锁定源姿势；有低透明度边缘背景。已保存为拒收候选及提示词，禁止接入。生成成功不等于资源可用。
- 3D转2D：用户不接受的比例、肌肉、脸型和姿势不会因导出PNG而自动变正确。正式纯2D路线禁止继续复用这批烘焙。
- 动作标签：六个按钮或六个不同动作ID不等于六套独立拳脚动画；后者仍需源帧对照与美术制作。
- AIR/CNS：等待帧、物理与状态切换必须一起研究；直接用通用计时器播放会造成空中停滞和突然倒地。
- source代码也需核对：CPSS源码中部分地址有不确定注释，两个末尾code bank基址重复，未经映射验证不应盲信输出。
- UI信息：尚未实现的巡回赛关卡不能写成“赢两局自动下一场”；本批只验证单场两胜、结果和重赛。

## 6. 角色/招式字典与背景设定方法

每个独立角色建立稳定ID、正式名、换装列表、固定参考版本/角色、战斗定位、对标理由、普通技语义槽、特殊技/投技/必杀/大招、输入与条件、源帧/几何/时序、判定/位移、消耗/取消、特效音效事件及验收状态。缺少证据的数值使用null，不填写看起来像真的帧数。

普通技语义槽是覆盖检查，不是独立素材数量。参考角色存在按键例外、共享姿势或近远距离分支时明确记录，不强行给拳击手补普通踢腿。角色背景包含身份、经历、动机、性格、关系、主场、出场和胜利台词；原创设定草案与原作事实分开。私有角色字典/背景保留在私有游戏仓库。

## 8. 全角色背景设定交付批次

16个独立身份的原创背景字典现覆盖经历、性格、参战动机、人物关系、主场、登场/胜利台词和独立通关结局草案。私有仓库 `docs/design/character-backgrounds.md` 供文字评审；角色档案页从同一字典读取，避免文档与界面各写一份发生漂移。换装不增加角色人数，街霸招式参考与原创身世明确分开。

本批 npm test 15/15、Vite build通过；浏览器实际打开角色档案，确认怪笑奶蛙的性格、登场台词和通关结局可阅读，窄屏滚动到详情正常。通关结局目前是档案文本，未接入街机通关动画或剧情模式，不能把设定完成写成玩法完成。验收截图留在私有仓库 output/qa/character-backgrounds.png，不将用户角色设定复制到公开知识库。
