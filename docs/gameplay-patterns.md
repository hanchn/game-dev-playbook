# 可复用抓捕与运输玩法

这些模式适合垂钓、光束抓捕、吊运和收集类小游戏。规则放在纯逻辑层，表现由引擎订阅状态或事件。

## 持续动作抓捕

一次尝试有明确状态：无目标、锁定并累计、成功或逃脱、冷却。目标必须在允许距离和范围内，持续满足条件才累计进度；离开范围或用户松手则按设计中断。

逃脱概率在一次完整尝试完成时抽取一次。逐帧抽取会让概率随帧率和抓捕时长变化。成年和幼体可以用不同概率、抓捕时长、收益和反击参数，但模型只读数据。

抓捕区域、视觉光束和实际操作难度一起验证：受惊目标若在达到时长前必然离开范围，系统虽有“成功代码”却实际上不可玩。先验证代表目标的速度、范围与时长，再扩展种类。

## 多载荷与飞行

载荷列表保存对象 ID、配置和抓取时间。总重量由列表计算，避免加减计数逐渐漂移。

- 重量可以影响速度、最高可维持高度、下沉速度和惯性。
- 随机偏移按间隔选择新目标，再平滑过渡；不能每帧随机跳坐标。
- 持续携带可以逐步损耗耐久，较重载荷损耗更多。
- 携带时长与重量分别调参，避免一个很轻物体立刻导致失控。
- 放生与交付清空载荷后，重量、保留时长和抓捕进度同步清理。

调参集中管理，先验“空载可控、小载荷可见、大载荷危险”，再看完整回合体验。不要把未经测量的参数称为最佳数值。

## 放生、交付与经济

交付区应判断位置，释放动作判断冷却。到达交付区后消费载荷并付钱，原位置放生只返还世界对象，不付钱。

收益用每个动物配置，垃圾收益为零；垃圾不增加有效交付数量。扣费和收益都应携带实际变动值，让 HUD 反馈与余额一致。余额扣到零后不能继续减为负数。

物体释放后有重新吸取冷却，防止同一个垃圾在一帧内反复扣费。一次误吸将其变为不可再次吸取的载荷；显示受伤和金币反馈不能再次执行业务扣费。

## 统一失败入口

攻击、飞鸟碰撞、误吸和载荷耐久耗尽都可能致命。统一坠毁入口执行：

1. 停止持续动作，清空锁定目标和进度。
2. 释放全部载荷并恢复其世界状态，不发交付奖励。
3. 发出一次坠毁事件。
4. 进入结算并停止本帧余下玩法处理。

匿名修复案例：一个实现只在“负重耗尽耐久”时放生载荷，直接碰撞扣到零只结束回合，导致动物仍留在载荷里。另一个实现结束后继续遍历邻近杂物，又吸入了第二件垃圾。统一失败入口与终态检查同时解决两类问题。

## 实例生命周期与轻量个性

生成、活动、被抓、放生、交付、出画回收是不同状态。被抓实例不应马上补一个新实例；原槽保留，交付后才按预算补生。天空和地面物体共用总预算，不因素材库扩容而增加同屏密度。

动物偶发停步、张望、啄食、摇尾等动作时，保持固定比例和根节点位置；受惊时中断休闲动作。选择下次动作时间应错开，避免所有动物同步表演。只复用已有动作时，应准确说明使用的是微动或既有帧，而不是新增完整动作。

## 数据扩展顺序

先验证少量代表：小型普通、成年反击、重型载荷、危险杂物、天空碰撞物。验证端到端后增加配置和素材，保持稳定 ID。

新增图鉴条目与新增可生成物体分开：没有可用资产的条目不能自动解锁并进入生成池。运行时默认值、持久化存档和调试注入分开，重置需要同时验证余额和解锁状态。
