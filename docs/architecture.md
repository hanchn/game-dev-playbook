# 小游戏架构与验证

目标是让玩法规则可独立验证，让引擎负责展示，让界面通过事件更新。换美术、增加图鉴条目和支持新屏幕，不应要求重写抓捕、收益或存档规则。

## 六层职责

| 层 | 负责 | 避免 |
| --- | --- | --- |
| 纯逻辑 | 状态、移动、碰撞规则、抓捕判定、载荷、收益、结束条件 | 引用 DOM、纹理、声音和引擎对象 |
| 引擎渲染 | 根据状态摆放精灵、播放动画、绘制光束、管理视觉对象池 | 重复决定奖励、逃脱或解锁 |
| UI | 首页、HUD、图鉴、结算、虚拟输入、加载反馈 | 每帧重建数字、直接修改经济数据 |
| 数据 | 类型参数、价格、尺寸、速度、动作、解锁顺序 | 用数组位置隐含物种身份 |
| 存档 | 验证、版本迁移、持久化、明确重置 | 将调试余额写进正式默认值 |
| 资产 | 原图、运行时图集、帧元数据、来源记录、验收记录 | 用生成成功代替实际动画验收 |

接口应小而稳定：创建、开始、推进时间、设置输入、触发动作、暂停、恢复、释放事件。渲染器读取快照，事件携带稳定 ID 和必要的数据；不能依赖 UI 文案来识别物体。

## 状态与时间

建议显式区分 `menu → loading → playing → result`，图鉴等覆盖界面记录进入前状态。只有资源解码、纹理建立和首帧准备完成，才进入 playing。图鉴关闭应返回原状态，而不是一律回首页。

| 状态或场景 | 模型时间 | 世界动画与 Tween | UI 动画 |
| --- | --- | --- | --- |
| 首页 | 不推进回合 | 不播放游戏动作 | 可播放封面反馈 |
| 加载 | 不推进回合 | 仅允许预热 | 加载反馈正常 |
| 游戏中 | 正常 | 正常 | 正常 |
| 图鉴 / 暂停 | 冻结 | 冻结 | 当前界面正常 |
| 结算 | 不推进回合 | 冻结背景 | 结算角色按要求播放 |
| 切入后台 | 暂停 | 暂停 | 按产品策略暂停 |

恢复后清理累计时间，不能把后台经过的几分钟一次性作为游戏 delta。限制单步 delta 可以防止瞬移，但不能替代明确的暂停策略。非循环动作完成后回到稳定姿势；重播应由用户点击或新事件触发。

## 事件、输入与幂等

- 输入层统一映射键盘、摇杆和触摸长按为动作，不让 UI 与模型各保存一份 beam 状态。
- `capture`、`escape`、`damage`、`delivery`、`penalty`、`crash` 等事件只在状态转移时发出。
- 持续动作可以读取状态展示进度，不需要每帧发奖励事件。
- 交付消费载荷后才发奖励；重复点击不能重复付钱。
- 任何致命损伤都走同一个坠毁入口，先清理目标与载荷，再进入结算。
- 帧内发生结算后，后续误吸、攻击和生成逻辑必须停止，避免“已坠毁却又装入一个物体”。

## 池与预算

图鉴可以收录很多类型，但同屏实例数量独立设限。计算动物、障碍、飞鸟、漂浮物、载具和装饰的总量；不要只限制一种鱼或动物。

载荷应占用原来的实例槽，隐藏被抓实例即可，不能一边保存 cargo 一边不断补生同种动物。完全出画后回收实例及其阴影、特效和关联碰撞数据。复用实例前重新设置位置、可见性、动作、方向、计时器、透明度和缩放，避免上一轮状态残留。

## 有效测试模式

纯逻辑注入随机源和时间，不用等待真实秒数。边界测试应验证规则结果，而不是镜像实现。

| 测试 | 核心断言 |
| --- | --- |
| 持续抓捕 | 未达到时长不成功，范围外不中，移动目标实际可抓 |
| 逃脱 | 每次完整尝试只判定一次，失败后有重试冷却 |
| 多载荷 | 重量累加，原实例槽保持不膨胀 |
| 伤害 | 冷却阻止每帧连续扣血，各致命途径释放全部载荷 |
| 误吸 | 一次扣费一次损伤，余额不小于零，垃圾交付无奖励 |
| 幂等 | 第二次交付 / 重复点击没有额外金币 |
| 生命周期 | 出画回收，长时间推进不超过实例上限 |
| 存档 | 默认数据、迁移、损坏输入、重置均可预测 |
| 暂停 | 回合时间、抓捕进度、世界位置保持不变 |

逻辑测试通过后仍要看实际渲染：手机和横屏布局、帧边缘、阴影、动画切换、加载后的第一帧、进入图鉴与返回。构建成功只能证明可构建，不能证明动画自然或性能合格。
