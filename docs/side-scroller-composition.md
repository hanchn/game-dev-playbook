# 横屏无限侧视地图：美术、支撑面与遮挡共用几何

适用：分层视差、可变地貌、池塘与坑洞、建筑和环境动物组成的横屏侧视游戏。来源是《恐龙消防员》2026-10-13—14 的真实返工；本文中的尺寸、透明度和时长是该项目标本，换项目必须重新测量，不能直接当默认标准。

源码基线：[5183fda：火山放大并后置](https://github.com/hanchn/dinosaur-firefighter/commit/5183fda08efb4b3ee2013c1f3dbf1469627dd81d)。[项目问题与验收台账](cases/dinosaur-firefighter.md) 保留用户拒收和待审状态。以下把「已经写入代码」「逻辑回归通过」「实机看到」「用户认可」分别记录；不互相替代。

## 1. 先定画幅、层序和共享坐标，再加素材

**失败 → 原因：** 上下露底、建筑悬空、火山山脚透出、角色被水层横切，往往不是少一张图，而是每层自己猜坐标、缩放和透明度。只描述“有多层”不能说明遮挡关系。

**方案：** 建立从远到近的层表，并区分世界坐标、镜头变换和屏幕 UI。当前项目逻辑画幅为 1100×570，基准地面 y=500，镜头跟随 `player.x - 0.3W`；地面和角色都调用同一模型的高度函数。ENVELOP 覆盖窗口会裁边，HUD 另按可见安全区缩放，不能只看逻辑画幅内没有越界。

| 内容 | 当前 depth | 镜头/透明关系与职责 |
| --- | ---: | --- |
| 日间天空 | −2 | 镜头位移系数 0.1；完整底色 |
| 夜间天空 | −1.9 | 与日间天空相同位移；alpha 0→1 过渡 |
| 火山与喷口烟 | −1.8 | 位于两套天空之后的显示顺序、全部树林之前；不依赖半透明树林显示山脚 |
| 日间/沼泽树林 | −1 | 镜头系数 0.35；整层 alpha=1，源图自身的枝叶透明轮廓保留 |
| 夜间树林 | −0.9 | 同树林位移；alpha 0→1 与日间树林混合 |
| 地面 | 1 | 世界高度曲线与土层纹理 |
| 场景对象 | 2 | 池塘、建筑、蛇、环境动物，以及对象附着火焰 |
| 主角与局部前缘 | 3 | 主角后局部重绘水前层、池底前缘和泥前缘；飞石也绘制于此层 |
| 近景草石 | 4 | 镜头系数 1.08；让出关键交互区域 |
| 天气 | 5 | 雨雾覆盖场景，不覆盖 HUD 的信息层级 |
| 受击闪屏 / HUD / 消息 | 16 / 20 / 26 | 屏幕坐标；消息独立于场景邻近提示 |
| 菜单 / 弹窗 | 30 / 40 | 屏幕坐标；进入覆盖状态需冻结玩法时钟 |

这里“之前/之后”以最终绘制顺序为准：天空先画，火山后画，再由树林和地面遮挡火山。不要仅凭 depth 名字判断远近。代码中 depth=10 的旧夜色蒙层已关闭，不应再叠加当作日夜方案。

**验收：** 同一视口逐层开关检查，左右移动、改变窗口宽高、夜间切换都看一遍；核对透明孔洞究竟是素材轮廓还是整层 alpha 泄露。证据：[层建立与 depth](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/app.mjs#L103-L135)、[镜头与昼夜更新](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/app.mjs#L482-L486)、[画幅配置](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/config.mjs)。

## 2. 远景体积以关键锚点定位，不用整层透明度补构图

**失败 → 原因：** 只看到火山飞石却看不到火山；放入火山后，完整山脚又露在树林前，像一张悬放的贴纸。旧版本火山高度 285，且降低树林整层透明度区分地貌，进一步暴露远景底边。

**方案：** 把喷口作为共享锚点：火山图、烟源和飞石起点共用 `volcanoPosition(camera)`。当前改为高 600 的火山，绘图左上 y 为喷口 y−0.25×高度，山体底部延伸到地面后；火山层明确后置到 −1.8，树林恢复 alpha=1。地貌差异通过专用树林和地表素材表达。600 只是本画幅和这张山体图的返工值；其他原图必须重新确认喷口在源图中的位置、山脚延伸和遮挡。

**验收：** 必须同时看到喷口、烟和飞石出发位置一致；在草地、砂石、沼泽、森林及昼夜下检查山脚不外露，镜头左右移动不穿帮。不能用“火山已经放大”代替实机审图。**此 600 高度、−1.8 层序修改已提交，但没有新的实机画面验收，不能记为通过。** 证据：[火山绘制与烟源](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L23-L26)、[喷发轨迹创建](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L74)。

## 3. 循环纹理与地貌过渡分别处理

**失败 → 原因：** 天空循环处出现竖缝；土层按区块填不同颜色，出现贯穿地面的色差墙。相邻图片都好看，不意味着边缘的云形、树冠、亮度与 alpha 能连接。

**方案：** 保留原 PNG，运行时生成派生纹理。项目用原宽约 9% 的重叠区，在预乘透明度意义下混合首尾，周期变为原宽减重叠宽；土层沿世界 x 取样，按高度曲线逐窄列贴合。地貌着色跨区块渐变，不按区块整矩形突变；负世界坐标的取模也要规范到正区间。

这是一种接缝缓和手段，**不是原始美术天然无缝的证明，也不是保真证明**：渐混会改变重叠区内容，可能产生双树冠、幽灵云、软带和重复节奏。导出资产时不得把派生结果冒充未修改源图。地形陡坡逐列位移也可能拉开草根，需要单独审坡度和采样密度。

**验收：** 镜头跨至少两个纹理周期，正反向经过所有接点；固定昼夜、天气与缩放对比同一接点。检查轮廓、颜色、透明边和运动时的跳变，不能只验证两端像素差或一张静止图。证据：[循环纹理处理](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/parallax.mjs)、[土层取样与渐变](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L11-L22)。

## 4. 水塘、滩涂和深坑共用占地，分别定义脚底

**失败 → 原因：** 鳄鱼池过小，水塘像贴在土上的装饰；滩涂远小于触发区；恐龙靴底悬在水面或穿过池底。主要原因是图片宽度、碰撞半径和模型下沉量独立猜测。

**方案：** 每种地物同时声明「完整画面占地」「岸面高度」「行走/触发区」「脚底深度」「前缘遮挡」。当前标本如下，不能把这些数字推广为所有水塘的规范。

| 地物 | 渲染几何 | 模型几何与效果 |
| --- | --- | --- |
| 水塘 | 宽 `2.25r`，完整半宽 `1.125r`；高 `min(136, 宽×源高/源宽)`；源水面在高的 0.49，准确锚到 `groundAt` | `floorAt` 在 `0.92r` 内以余弦下沉；中心深度 `min(50, 图高×0.51−9)`，脚底留前缘余量 |
| 泥洼/滩涂 | 宽同为 `2.25r`，源比例约 0.333，后缘 anchor=0.40；去掉旧 `+18` 悬空偏移 | 在 `0.88r` 内平滑下陷，中心深度 `min(22, r×2.25×0.333×0.15)`；本例约 15–17 像素，并降低地表草带 |
| 深坑 | 宽仍按完整 `1.125r` 半径预留；源图表现陡壁和暗底，后缘 anchor=0.16 | 踩入触发区后进入独立 falling 状态；完整主角向坑中心下落、缩小、渐隐，不能用水平硬裁切模拟“被切掉” |

普通池与鳄鱼池用不同 r，并应提供足够水下净空间。容量、是否有水和碰撞深度是不同状态：当前模型干池仍保留洼地脚底，不等于恢复成平地。雨水回灌、抽干、重新有水后，要同步鱼鳄显隐、交互与遮挡。最新玩法约定以项目需求为准，不能沿用已被覆盖的“干池鱼持续蹦跳”记录。

`groundAt` 表示岸面/基础地形，`floorAt` 表示角色实际接触底面，不能把两者混用。当前源比例在模型中仍有 `763/2060` 常数；换图时必须同步校准，下一步宜由同一几何元数据派生，避免换 PNG 后模型未变。

**验收：** 检查岸左、浅水、深水、岸右、干涸、回灌七个状态，确认靴底、水面、池底和动作桶口关系；泥区慢行与跳过分别检查；坑洞录制完整掉落过程而非只截最后一帧。证据：[池塘渲染几何](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L4-L6)、[池鱼鳄组合](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L29-L35)、[岸面与脚底高度](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L23-L24)、[掉坑完整角色动画](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L39-L54)。

## 5. 建筑实际脚点、支撑基面和洞顶平台分开校准

**失败 → 原因：** 房屋、洞穴、树根有漂浮间隙；将图片底边统一设为 95% 仍不对；把角色的行走地面直接抬到洞顶又造成瞬移。透明画布底边、实际落脚点、建筑完整底边和可站立岩顶并不是同一条线。

**方案：** 从源图 alpha 轮廓实测脚点，保留阈值、源尺寸和结果。当前 tree/house/cave 的 y 锚分别约 0.9681 / 0.8982 / 0.9485，渲染高度 300 / 280 / 235；数值只对应这些源件。宽建筑应在完整基础宽度内形成平基，再用 bank 平滑接坡。贴一块阴影不能替代支撑面。

洞顶用独立单向平台。项目根据实际岩顶而非最高叶片，定义中心 `cave.x+7`、半宽 28、高度 `groundAt(cave.x)−188+12d²`；只在下降穿越顶面时落脚，保持 `supportId`，走出边缘后落下。上跳穿过侧视平台与地面蛇碰撞分别处理；阴影随支撑面移动。

**当前边界：** `groundAt` 对建筑的平基半径仍取玩法 `r+18`，而布局 `footprintRadius` 为房屋/洞穴预留 145/150。完整底边的支撑范围与布局占地尚未统一为一份元数据，因此“脚点已测量”不能证明所有随机坡面均已无悬空。

**验收：** 平地、上坡、下坡各看建筑左右脚及中间基座；角色由左右起跳上洞顶、走出、落地、躲蛇各走通一次。证据：[源图脚点记录](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/data/scenery-anchors.json)、[洞顶曲线与平台查询](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L40-L41)、[下降穿越与支撑状态](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L78)。

## 6. 水下角色用透水合成，近景让出交互信息

**失败 → 原因：** 鳄鱼只剩西装横条、头尾丢失；恐龙靴子被过浓的整池重绘吞没；底部草石遮住陷阱。先画身体再用水平裁框截掉上半身，不能表达潜水。

**方案：** 鳄鱼完整绘制，依据帧内实际包围盒和脚点确定水下 root；游泳只播放游泳帧，不能混播走路或张嘴帧导致水位跳动。本例鳄鱼画面宽约 238、身体 alpha=0.82；其后以 alpha=0.25 局部覆水，池底前缘单独重绘，保留水下西装和头尾可读性。角色踩水时也使用局部水前层，而不是将整池以 0.67 再盖一遍。

近景的职责是补空间层次，不是遮住玩法错误。每次布置草石都预留池岸、取水点、坑边、蛇和伤害预警的可见区。当前近景只按 `mud/hole` 中心附近让位，尚不是完整交互安全区系统；以后增加对象时必须扩充遮挡规则，并按完整 `1.125r` 画面占地复核。

**验收：** 鳄鱼面向左右游过全池，逐帧看身体连续性；恐龙下水、舀水和离水全过程不能露出悬空靴底或平直断面。近景开关前后，危险和交互仍可识别。证据：[水下整身与局部覆水](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L29-L35)、[水泥前缘与近景让位](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L57)、[游泳帧与脚点](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/characters.mjs#L5-L6)。

## 7. 无限生成也需要布局预算与连续通行区

**失败 → 原因：** 兔鹿在池岸抖动或卡死；泥洼后加到洞旁，与坑洞重叠；跨区块出现挤压。每帧发现进池就反向会让动物在同一点反复换向；只比较中心点或玩法 r 则忽略完整贴图。

**方案：** 生成完成后统一排布所有地物，包括特殊洞旁泥洼和 fallback 深坑。按完整画面半径预留距离，再尝试候选位置；无合法位置宁可减少对象，不强塞。项目 `footprintRadius` 对池/泥/坑使用 `1.125r`，对建筑单列占地；最终 `layoutHazards` 把每个危险物限制在区块内的净距边界，并与固定物及已放危险物留距。它检查的是危险物放置，不代表所有对象两两关系都已经校验。

NPC 先从可走域扣掉池塘、坑洞与阻挡建筑，再选足够长的连续区间作为巡逻域，区间边界停留后转向。模型位置移动和步态时间同步，停留不继续走路帧。当前建筑导航阻挡宽度仍有玩法 r 与完整贴图宽不一致的可能，需要实机审身躯净空。

项目每块宽 2400，只保留玩家所在块及左右各两块，共 5 块。要验相邻区块拼接处的完整美术占地和安全通路，不能以本块生成成功证明边界安全；跨边界的大固定物、后续新增对象还应显式登记邻块预留区。

**持久性边界：** 这实现的是持续延展与有界内存，不是永久保存整个世界。远块会删除，返回后用当前随机源重新生成；没有稳定的逐块种子和对象状态存档，不能承诺旧池水量、火灾状态及动物位置原样保留。需要永久世界时应加入块种子、已修改对象差量及版本化存档。

**验收：** 多个随机样本检查占地净距；向左和向右跨块、折返、连续经过池岸，观察 NPC 是否有足够巡逻距离。记录实际驻留块/实体数，回收后检查影子、粒子及交互引用也被清理。证据：[区块生成与回收](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L10-L20)、[最终布局检查](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L29-L39)、[连续通行区和 NPC 巡逻](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/model.mjs#L42-L63)。

## 8. 昼夜、天气与验收证据保持可解释

**失败 → 原因：** 夜晚只调暗整屏；天空出现说不清的飘动白点；用“60 FPS”单次读数代表优化完成。气氛层如果没有明确来源与节奏，会变成干扰物，也会掩盖真正的遮挡问题。

**方案：** 日夜使用独立天空和树林原图，过渡时同时更新，暂停由玩法时钟冻结。当前周期 140 秒，65–70 秒转夜、135–140 秒转日；这只定义现有切换，不代表已实现完整太阳轨迹、逐物体夜间照明或生态昼夜系统。雨、雾和风分别有明确表达：已删除原本用椭圆模拟、被用户看成白点的大风粒子；风通过烟火摇曳等现有对象表达。固定星点来自夜空原图，不能把用户说的“独立飘动白点”未经核查就解释成星星。

**验收与记录：** 每次修正记「失败画面 → 具体原因 → 源码/素材变更 → 同状态复查 → 未通过项」。记录源 commit、素材版本、视口、天气、昼夜、镜头位置与动作阶段；截图检构图，短视频或实际播放检接缝、掉落和步态，逻辑测试检状态边界。浏览器观察到一次约 60 FPS，只能证明该时刻的快照；持续性能需要覆盖移动、喷发、多动物、天气、昼夜切换和区块回收的采样，并保留时长、设备和分位数。

证据状态应使用以下含义，不合并为一个“完成”：

| 状态 | 可支持的结论 | 不可推导的结论 |
| --- | --- | --- |
| 源码已提交 | 指定实现可追溯 | 当前页面已刷新、视觉已通过 |
| 逻辑回归通过 | 被覆盖规则在测试条件下成立 | 贴图漂亮、比例自然 |
| 实机观察 | 指定版本/条件下确实看到效果 | 所有随机地图、设备和长时段均稳定 |
| 用户认可 | 指定作品/范围获得认可 | 后续修改自动继承认可 |

截至本记录，新增火山构图仍待新实机验收，其他新美术不得因规则回归通过就写成用户认可。证据：[日夜变体与进度](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/app.mjs#L482-L486)、[天气实际绘制](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/renderer.mjs#L59)、[性能快照字段](https://github.com/hanchn/dinosaur-firefighter/blob/5183fda08efb4b3ee2013c1f3dbf1469627dd81d/src/app.mjs#L556-L571)。
