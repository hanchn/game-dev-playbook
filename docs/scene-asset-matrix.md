# 场景与资源矩阵

先列出屏幕和状态，再安排出图。UI 外壳保留空槽，标题、说明与数值独立渲染，避免烘焙文字使布局和本地化失控。

| 场景或状态 | 应准备的图 | 应独立实现的内容 | 关键验收 |
| --- | --- | --- | --- |
| 首页封面 | 主视觉海报、开始按钮、可选标题标识 | 按钮文案、版本信息、声音状态 | 角色结构可信，点击区与按钮一致 |
| 玩法世界 | 无角色背景、前中后景、地面或水面装饰 | 实体、碰撞、目标区、HUD | 背景等比铺满，实体不从默认点闪现 |
| 天空和视差 | 云、远景轮廓、独立光效 | 移动速度、遮挡、回收 | 远近层级明确，不随 UI 缩放变形 |
| 加载 | 轨道外壳、进度填充、可选小角色动画 | 真实进度与进入条件 | 只出现一个加载入口，资源准备完再切换 |
| 图鉴 | 卡片外壳、展示空间、返回和切换图标 | 主体动画、名称、说明、价格与解锁状态 | 卡层切换可读，无邻帧和内容裁切 |
| 抓捕成功 | 角色成功动作、轻量奖励特效 | 奖励数值、飞向 HUD 的轨迹 | 奖励落点是图标，动画不重复结算 |
| 抓捕失败 | 沮丧动作或失败反馈 | 扣减数值、损伤提示 | 能清楚识别失败原因，数值不低于规则下限 |
| 新内容解锁 | 与图鉴相同的卡片组件、揭示特效 | 解锁名称、确认或收录动作 | 与图鉴保持同一外壳，收录后关闭 |
| 结算 | 弹窗外壳、成功和失败标题、角色动作 | 收益、再来一局、返回入口 | 角色和载具完整，背景玩法暂停 |
| 设置 | 设置框架、声音或操作图标 | 状态、焦点、返回行为 | 图标风格一致，点击和键盘均能退出 |
| 触屏 HUD | 摇杆、操作按钮、货币与耐久容器 | 数字、长按状态、操作说明 | 安全边距、比例和触摸尺寸独立可控 |

## 分层关系

世界层、角色层、特效层和 UI 层分别承担明确职责。阴影跟随主体但不使用整张透明图集的矩形投影。弹窗上的角色动画独立于背景角色，打开弹窗时冻结背景状态，避免两处同时播放造成重复或闪烁。

场景中的随机位置、大小和出现时间都需要边界。位置不能为了避免同侧而永久禁止中间区域；前后距离变化应同步影响大小和视觉衰减。

## 状态资源的共享

图鉴、解锁和结算可以共享展示组件，但不应共享一个不断变化的全局动画状态。每个展示实例有自己的播放进度、停止条件与销毁逻辑。

装饰彩蛋可以设计为一次性触发：一次场景会话只播放一次，完成后停用并回收。随机方向由运行时镜像决定，保持资源真实朝向记录清楚。

## 屏幕适配

背景采用等比覆盖或按设计扩展，不拉伸成不同形状。UI 框架采用等比缩放、锚点和安全区；文字所在空槽需测试极端数值、长名称与窄屏。卡片可重排而不是靠横向硬裁切隐藏错误。
