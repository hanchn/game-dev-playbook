# 行走与逃跑序列帧：制作、修正与验收

整理日期：2026-10-10。来自四足动物、双足禽类与逃跑角色的实际迭代。这里只保存可复用方法，不包含私有项目素材。

**先确认近远侧肢体确实交替，再校准尺度、步幅与播放速度。** 源图缺少对侧动作时，增加帧数、调帧率、调整顺序或整体镜像，都不能补出正确的换腿姿势。

通用画布、图集和透明边界规范见 [序列帧生产与验收](sprite-animation.md)。

## 1. 先区分源动作与播放问题

暂停动画，逐格看完整角色，再用同一资源做慢速循环。按直接观察到的症状定位，不先修改帧率。

| 可观察症状 | 首先核对 | 修复方向 |
|---|---|---|
| 外侧腿一直迈，内侧腿不接替 | 两个半周期是否交换近远侧腿的动作 | 重做源姿势，先验证相反关键姿势 |
| 四足角色只有前腿换，后腿重复 | 近前、远前、近后、远后是否分别有相位安排 | 重做缺失的腿部动作，不复制两腿摆动四次 |
| 腿在走，手臂不摆或始终同侧在前 | 肩、肘、手腕身份及腿臂关系 | 重做摆臂姿势，检查遮挡与末首衔接 |
| 一受惊或换速就抽一下 | 是否用全局时间乘当前帧率选帧 | 连续累积相位，换速不重置 |
| 停住仍走、慢走快速踏步 | 动画推进是否独立于位移 | 世界行走按实际路程推进，静止保留相位 |
| 按路程播放仍滑步 | 支撑脚在源帧中的行程及运行步幅 | 修正支撑姿势，再校准步幅与显示尺度 |
| 身体忽大忽小、头部漂移 | 是否逐帧按全身包围盒缩放或对齐 | 公共尺度，稳定身体标志配准；真实形体变化需重做 |
| 最后一帧回第一帧顿一下 | 姿势、支撑关系、锚点与播放序列 | 单独检查末→首，重做错误过渡 |
| 尾巴、脚切断或露邻格 | 源画布、帧矩形、留边及镜像偏移 | 修正画布与导入配置，双向验证 |
| 预览正常，游戏或图鉴还是旧动作 | 实际加载路径、资源版本、帧序列与更新入口 | 统一资源配置，完整刷新并核对两个实际入口 |

“像素不同”“有八张图”“测试通过”都不是换腿正确的证据。

## 2. 出图前先写肢体身份与相位

侧视角色用**近侧/远侧**命名，比只写“左腿/右腿”更容易核对。朝向翻转不改变肢体身份，整只角色镜像也不等于换腿。

- 四足：近前、远前、近后、远后，分别指定身体连接位置、支撑时间与回收时间。
- 双足：近腿、远腿，两条腿轮流承担前伸、承重、后蹬与回收。
- 逃跑角色：同时记录近远侧肩、肘、手腕。采用相反摆臂的动作方案时，近腿前迈配近臂后摆，另一半周期交换；不能只移动拳头。

先定义目标是慢走、快走还是跑步，再制定相位表。四足的不同步态不能共用一套接地安排；双足姿势不能直接从四足母版换皮。

每帧至少记录：四肢身份、哪些脚接地、哪些脚离地、运动方向、遮挡层次及下一帧的过渡。可以按下面的字段填写，不用一句“自然走路”代替：

| 帧号/相位 | 近前或近腿 | 远前或远腿 | 近后 | 远后 | 手臂 | 支撑脚与下一帧 |
|---|---|---|---|---|---|---|
| 按动作方案逐行填写 | 前伸/承重/后蹬/回收 | 同左 | 四足填写 | 四足填写 | 双足角色填写 | 接地脚、遮挡、过渡 |

验收时沿同一条腿追踪整个周期，确认它完成前伸接地 → 身下承重 → 后蹬 → 离地回收，再追踪其对侧。前腿、后腿分别核对，不能只凭一只爪子抬起就放行。

八帧是本次四足代表样本的制作选择，不是通用标准。帧数和接地次序应服务于目标动作；六个可靠姿势优于凑入两个重复姿势，但删帧之后仍须验证完整循环。

## 3. 先验证两个相反关键姿势，再补完整循环

1. 锁定完整角色参考：相机、朝向、头身比例、花纹、服装、尾巴及光照一致。
2. 先制作两张能证明近远侧动作交换的完整关键帧，逐条核对腿与手臂身份。
3. 关键帧通过后，补承重、经过、后蹬、回收等中间姿势；逐帧生成也可能漏腿、加腿或重复动作，仍要检查。
4. 拼成循环，检查所有相邻帧及末首连接。慢速确认动作关系，目标速度确认节奏。
5. 代表样本接入真实游戏后再扩展同类角色，每个新增角色仍单独验收。

连续两次整张图集生成仍重复同侧动作时，停止该批量方式，回到关键姿势验证。这个次数是本次实践采用的止损规则，可按项目成本调整；不能无限追加候选而不改变输入与验收方法。

### 参考图要分工，输入顺序要核对

在本次编辑流程中，把已验收步态母版作为第一张编辑目标、旧素材仅作为造型参考，比以错误旧图为目标更容易保留换腿关系。不同工具的输入语义可能不同，必须确认哪张是编辑目标，并在提示词中分别声明“动作参考”和“外观参考”。

四足角色可以复用可靠的四足动作母版，再检查新物种的比例与遮挡。禽类另做双足姿势参考。彩色近远腿示意图可以约束脚点和层次，但输出必须检查指示颜色是否残留、腿根是否被毛发或羽毛自然覆盖。

提示词应包含明确帧号、肢体身份、接地/离地、固定镜头与尺度、完整轮廓、透明留白和循环衔接。保留完整输入与提示词；生成结果只是候选。

## 4. 配准与打包只修导入，不修解剖

每张完整角色使用相同画布和公共等比缩放。记录原画布到运行图集的比例、每帧平移、源矩形、朝向、脚底或身体锚点。原图保留，运行版本另存，使用项目引擎的纹理帧接口导入。

配准参考头部、躯干等稳定区域，避开举手、摆尾和抬脚。允许整体平移修正构图偏移；禁止逐帧按可见边界改变尺度。若头、身体本身变形，或者支撑脚关系错误，配准无法修好，必须重做源帧。动作需要的起伏也不能被配准全部抹平。

图集打包是对已合格完整帧的格式整理。它不能通过拼接身体、拉伸腿或切掉错误部位，伪装成源动作修正。导出后检查安全边、空帧、透明光晕、邻格泄漏，以及两种朝向的偏移。

### 骨骼拼接试验留下的教训

本次试验出现残留腿、过长大腿、关节接缝、腿部拉伸、尾根错位、头部后缩及毛感丢失。问题说明该批拆分素材与绑定未达到要求，不能据此推断骨骼动画技术本身不可用。

若以后采用分层骨骼方案，需要为实际关节绘制部件，补齐隐藏区域与毛发重叠，确认关节中心、连接点、骨长及遮挡。按颜色分界裁开腿不等于按关节拆分；数学约束通过也不等于接缝自然。尾巴下垂等不同形态还需对应素材或可变形结构，单纯旋转一张上翘尾巴不能保证轮廓正确。

这些要求未验证前，不把拼接试验安装为正式资产。本次最终回到完整角色序列帧，并先验证近远侧换腿。

## 5. 世界行走按路程推进，独立展示按时间播放

世界行走的通用关系：`phase += 实际路径长度 / 单周期步幅`，再由动作定义的播放序列选择帧。斜走用路径长度，停步不推进，转向与换速保留连续相位。边界碰撞后用约束后的实际位置差，不能把被阻挡的速度当作路程；瞬移或重置也不能当作一步。

步幅按照支撑脚行程、显示尺度与目标速度校准。距离驱动能修复停步和换速时序，但不能纠正源帧缺失对侧腿或支撑脚漂移。

图鉴与预览没有实际行走距离，应独立按时间推进可见角色；隐藏卡片停止更新，重新显示不累计隐藏期间的假路程。世界暂停与界面展示采用各自的时间控制。

播放序列由实际动作决定，不能把图集格子顺序默认当作正确顺序。跳过重复帧前后要检查相邻与末首衔接；删帧不能创造缺失动作，也不能替代源图重做。

## 6. 用分级验收代替“已经做好”

| 状态 | 所需证据 | 不能推出的结论 |
|---|---|---|
| 生成候选 | 原图、输入、提示词、工具、版本与相位方案 | 动作正确 |
| 技术边界通过 | 帧矩形合法、非空、安全边、比例与来源记录 | 换腿自然、无滑步 |
| 逐帧视觉通过 | 肢体身份、支撑关系、比例、所有相邻与末首检查 | 已验证真实游戏 |
| 已接入、待游戏验收 | 运行资源及入口可追溯，保留替换前版本 | 游戏流程或用户已认可 |
| 真实游戏通过 | 具体版本、场景、动作与实际播放证据 | 未检查角色也通过、用户已认可 |
| 用户认可 | 明确反馈及对应版本、范围 | 代表样本能替整批签收 |

失败候选保留并标记 `rejected`，写清帧号、原因和替代版本。测试或构建结果单独记录，不提升视觉状态。本次狗样本获得“好像对了，放到游戏看看”的反馈，只支持接入验证；其余批量角色接入后仍需逐个审查。未观察到的失败逃跑流程不能写成已通过。

### 每批必查

- 慢速（本次使用 0.25 倍）、暂停逐帧、目标速度与加速状态。
- 每一条腿的完整周期，前后腿同时核对；逃跑角色同时核对肩肘摆臂。
- 所有相邻帧和末→首，身体比例、支撑脚、尾巴与头部连续性。
- 实际游戏尺寸、图鉴大图、左右方向、深浅背景。
- 停步→继续、正常→加速、边界转向及项目实际存在的动作切换。
- 涉及捕捉、释放、坠毁、逃跑和重开时，在对应游戏流程观察；独立预览不能替代。
- 核对游戏与图鉴实际加载同一批准版本，完整刷新后仍正确。

预览工具至少提供角色选择、慢速、暂停、逐帧、换向和完整帧网格。它用于定位问题，最终验收仍在游戏中进行。
