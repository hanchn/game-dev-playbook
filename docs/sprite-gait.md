# 行走与逃跑步态专项经验

整理日期：2026-10-09。以下为通用排查与验收方法，生成候选不能视为已验收资产。

## 从症状拆分原因

| 症状 | 首先检查 | 正确修复 |
|---|---|---|
| 一受惊就抽一下 | 用时间乘变化的帧率 | 累积位移或积分相位，换速不重置 |
| 停住仍走、慢走快速踏步 | 动画时钟与运动独立 | 距离驱动，静止暂停步态 |
| 每半周期还是同一条腿在前 | 源帧是否真实交换腿的身份 | 重做姿势，不能只调播放顺序 |
| 第末帧回首帧顿一下 | 循环姿势、支撑脚、身体锚点 | 单独检查末→首，必要时重做 |
| 身体上下漂移、忽大忽小 | 包围盒对齐与逐帧缩放 | 固定尺度，以躯干/髋部对齐 |
| 尾巴或脚切断 | 安全边、镜像与源矩形 | 修正源画布/帧矩形，双向验证 |

## 摆臂补充

摆臂不能仅看轮廓是否有两只手。明确近侧与远侧肩、肘、手腕的身份：近腿前迈时近臂后摆、远臂前摆；半周期后双方交换。近臂需在躯干前的正确遮挡层，远臂在躯干后。手臂不能整周期固定同一侧在前；腿正确而手臂重复仍然不合格。跑步的肩和肘需要连续摆动，不能只移动拳头。

一次生成整张图集连续失败时，先做两个相反接触姿势验证前后肢身份，再补中间相位，不继续盲目批量。关键姿势仍需保持相同相机、角色比例与骨骼长度。

## 制作步态图的要求

先画动作相位表再出图。双足走路至少区分近腿接地、承重、远腿经过、远腿前伸，以及交换双腿后的半周期。跑步还要包含回收与腾空。四足步态需要分别指定四条腿的相位和支撑关系，不能把两腿摆动复制四次。

八帧是本次代表样本的起点，不是所有动作的通用最优帧数。增加帧数不会自动补齐动作；八张类似姿势仍然是失败。提示词应写明确帧号、脚的身份、接地/离地关系、固定镜头与尺度、透明边距、末首衔接。生成结果只是候选。

保持角色头、躯干、服装、花纹和视角一致。每格固定画布与统一尺度；不按每帧可见边界重缩放。身体锚点应来自稳定部位，摆动尾巴、手脚不能决定身体位置。

## 运行时匹配

通用关系：`phase += 实际路径长度 / 单周期步幅`，再根据作者定义的帧序列选择帧。斜走用路径长度，转向不清空相位，停步不推进。碰到边界时用约束后的实际位置差，不能把被阻挡的速度当作已经走过的距离。

步幅要按画面里脚的支撑行程校准，与显示尺度、透视和物种匹配。距离驱动只解决换速和停步的时序问题；源帧的支撑脚漂移仍会造成滑步。

图鉴、世界、逃跑和载荷展示分别处理。可见卡片才推进动画；隐藏后再次显示不能把未观察到的坐标跳跃算成一步。暂停窗口冻结世界。镜像后偏移方向也需要验证。

## 验收门槛

1. 每个现有角色逐帧检查，明确近/远侧脚的身份及支撑关系。
2. 0.25倍速检查每对相邻帧与末首；1倍和受惊速度检查节奏。
3. 实际尺寸、图鉴大图、左右方向、深浅背景均检查。
4. 游戏中复现停步→继续、正常→受惊、边界转向、捕捉→收舱→释放、坠毁→逃跑→重开。
5. 自动检查空帧、合法矩形与透明安全边；通过仅代表技术边界合格。
6. 留下源图、完整提示词、工具、版本、网格、锚点、步幅、失败原因和实际播放证据。未验收不能标记 approved。

建议提供基于项目引擎的同屏预览工具，支持慢速、暂停、逐帧和换向；它是验收辅助，不替代真实游戏。

## 独立生成帧也需要完整循环验收

逐帧生成不能保证模型执行动作相位表。即使头部尺度接近，末帧仍可能重复对侧姿势，让手臂方向在末首连接时跳变。逐帧检查近远侧肩、肘、手腕和腿的身份，保留完整提示词；失败候选不得安装。

固定贴图的关节动画可约束骨长、半周期交替与脚的支撑高度，但裁切纹理的接缝、遮挡及关节外观仍须验收。数学约束通过不等于画面自然。

## 2026-10-10：先验证换腿，再扩展角色

用户观察到“外面的腿一直在迈，里面的腿不接替”时，应直接重做源姿势。增加帧数、改变帧率、调播放顺序，都不能制造源图中不存在的对侧动作。

给四足角色固定四个身份：近前、远前、近后、远后。近侧与远侧用遮挡、光照和身体连接位置识别，不能把整只动物镜像当作换腿。每条腿都要经历前伸接地 → 身下承重 → 向后蹬地 → 屈曲回收；两组半周期必须分别检查前腿和后腿，而不是只看前爪抬起。

四足慢走可以制定四拍相位表，双足禽类采用左右交替；跑步角色还需明确相反摆臂、回收与腾空。物种和速度不同，不共用一套姿势提示词。

连续两次整图生成仍重复同侧动作时，先停止整图批量。独立生成一张完整角色的固定参考帧，再逐张改变肢体姿势；先核对相反半周期的两个关键姿势，再补中间帧。每次明确哪个输入负责角色造型、哪个负责姿势，旧错误图集只能做造型参考。逐帧生成同样可能漏腿、加腿、重复支撑关系，必须拒收并重做。

所有完整帧使用相同画布、身体坐标和统一尺度。打包到引擎图集属于格式整理，不能按每帧包围盒单独缩放，也不能用身体拼接或拉伸腿修源比例。保留原始大图，运行版本可统一等比缩小；记录原画布到图集的比例以及脚底锚点，避免导入后又产生大小跳变。

验收分开记录：生成候选、技术边界通过、逐帧视觉通过、真实游戏通过、用户认可。代表角色通过只证明流程有希望，不能替其他角色签收。新素材必须同时替换世界和图鉴使用的资源，测试停步、受惊换速、转向、收舱和释放；逃跑角色需要在实际失败流程检查摆臂。经验仓库只存通用方法，不上传私有游戏素材。
