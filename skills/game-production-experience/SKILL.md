# 游戏美术与UI生产经验包

先读取项目约束和现有资产清单。复用的是生产方法与验证结果；游戏玩法、经济数值、对象数量及美术风格仍由当前任务决定。

## 锁定后再扩展

1. 将用户确认的主视觉保存为参考版本：主体、载具、镜头、材质、配色和实际朝向。旧稿、失败稿保留来源及状态，不能覆盖成“最终稿”。
2. 先实际播放代表动作和四类对象：普通主体、长尾主体、宽翼主体、柔性触须主体。角色需检查坐姿、站姿和结算衔接，站立身高应超过坐姿。通过后再批量扩展，不以静态缩略图或自动边界检查替代播放验收。
3. 固定帧画布、透明安全边、头部尺度及髋部锚点。尾巴和翅膀不是稳定锚点。不要逐帧缩放包围盒，也不要用整体拉伸修补船或飞碟形变。固定载具可以与动画驾驶员分层，但源帧若已含载具，不能再叠第二个底盘。

需要具体UI模板和出图提示时读 [UI模板](references/ui-production.md)。需要定位已发生的错误和完成交付时读 [验收清单](references/validation.md)。项目已有 `sprite-animation-production` 可继续用于序列帧专项检查；不必为普通UI修改重复加载全部动画指导。

## 导入与运行的稳定条件

- 清单记录原图真实尺寸、每帧区域、固定偏移、朝向、稳定尺度、UI槽位与来源。使用引擎纹理帧或SVG视口包装裁图，保留原像素；不能猜测等分后忽略裁切和邻帧。
- 帧内裁切与对齐位移分层：先隔离当前格，再移动格的外层。把偏移直接加到整张图集的背景位置会露出相邻格。
- 加载完成包含图片解码、UI图标/数字、纹理建立和首次绘制；依已确认的入口布局展示加载状态。默认先准备场景，再揭开游戏，避免素材逐个闪入。
- 对象创建后先定位，再显隐；回收时一起关闭主体、投影与碰撞，避免默认 `(0,0)` 的阴影闪烁。
- 数字和HUD按值变化更新，动画只运行在当前可见卡片；进入覆盖界面时冻结背后游戏逻辑和角色动画。先测帧率、CPU开销、实际存活/可见实体与纹理预算，再针对瓶颈修改。

将发现的真实错误追加到对应案例，不把某个游戏的数量、逃脱率或收费规则升级为通用限制。
