## 制作顺序

沿用用户已认可的角色设计和画风。用内置imagegen生成四个明确动作阶段，保留实际源图、精确prompt、参考图/输出SHA；先用一个角色验证，再扩角色。原四帧、失败稿、补帧、视频和来源记录都存入所属游戏项目；私有角色不复制进公开知识库。

四源先验收，不以四格出图成功代替通过：
- 相机、画布、角色尺度统一，头身比例和四肢粗细稳定。不能按每帧全人物bbox居中或缩放。
- 站立以双脚接触位置为基准，结束回到起始脚位。允许的支撑脚枢转需明确标注，不把生成漂移当动作。
- 用起始姿势两只脚掌中最低的实际接触位固定 floorY（图像坐标向下为正时取接触点 y 的最大值）。整段倒下动画共用这条水平线；倒地后的头、肩、躯干等实际承重接触部位落在此线上，不能穿地或整体悬空，也不能把倒下后的脚底或人物 bbox 当成新的地面。腾空起落共用此线。倒下是终止动作，不要求末帧双脚还原站姿；站立循环才检查脚位还原。
- 看四源同坐标叠影、左右脚接触点、头/躯干地标和安全包络，记录真实尺寸与裁区。不能把1254原图按1280预览坐标裁切；跨格手脚先完整提取再共同注册。
- 原四帧有形体变化要定点重绘源图；只平移能修画布注册，不能修头变小、腿距改变。

## 四到十二

现成工具 `tools/animation-lab/scripts/rife-four-to-twelve.py` 使用官方本地RIFE v4.6。运行前必须有源门禁JSON，绑定四张PNG的SHA、复核者和地面规则：

```json
{"sourceAccepted":true,"reviewedBy":"actual-visual-review","keys":[{"sha256":"..."},{"sha256":"..."},{"sha256":"..."},{"sha256":"..."}],"groundPolicy":{"floorY":650,"leftFoot":[210,650],"rightFoot":[500,650],"startEndRestored":true}}
```

```sh
python tools/animation-lab/scripts/rife-four-to-twelve.py --keyframes /absolute/keys --source-gate /absolute/source-gate.json --output /absolute/new-version --clip punch --label 出拳 --asset-prefix relative/new-version
```

RIFE默认1/4/7/10为原关键帧，邻帧t=1/3、2/3。真实绘制中间帧可按动作阶段重新分配时槽：例如回收复杂的踢击用1/4/7/12保留四源，把末尾停留改成半回收、高提膝回收、放脚和落稳，manifest显式写`sourceKeyframePositions:[1,4,7,12]`并保存每帧来源。不得仍声称默认1/4/7/10，也不能把复制帧当新增绘画。倒地等终止动作使用`--terminal`，末段保持最后姿势；不能循环站起。奇数PNG画布仅视频右/下补1px，原PNG坐标不变。RIFE输出为保留暗背景RGB，不能冒称透明游戏精灵。

大位移/遮挡变化易出现缺手脚、熔边、虚化。实际逐帧与慢放找坏帧，必要时用内置imagegen定点绘清晰中间姿势，记录为`generated-inbetween-repair`。不得靠锐化、交叉淡化或复制帧假装修复。用户认可某个补帧版本的效果不代表此算法适用于所有动作。

## 交付与QA

提供4源、12帧、图集、视频、manifest和完整来源；在关键帧动画测试页实际查看。源图通过、文件/帧数通过、动画美术通过分别记录，失败版本仍可对照。确认首末脚位/地面线、虚化、轮廓/服装漂移和全帧安全范围后才推广其他角色。播放器整段只用一次固定变换；异尺寸输入拒绝播放，终止动作不回环，异步切动作不能闪回旧序列。

受击动作必须包含疼痛表情阶段：受击起始挤眉/眯眼、峰值闭眼或痛呼、恢复阶段仍有余痛；禁止全程微笑或仅身体位移。面部身份、眼睛位置及头部比例固定，表情与受力时序同步，四源和补帧都逐帧验。

新增实测规则：生成器返回尺寸不保证方形或固定1254。先读取真实宽高，只按已确认共同像素倍率等比转换，以透明边缘pad/crop恢复合同画布；禁止将不同长宽比强拉成768²。逐帧检查运动阶段单调性：抬手准备不能中途突然降低再跳到峰值，单张清晰与地标稳定不足以通过。修复中间姿势后保留旧raw与具体错相原因。

动作入口应明确区分源图未完成、已知失败、透明候选、美术通过；视频/PNG存在并不意味着完成。角色内通过后再做跨动作头宽、腹宽、脚掌长度和起始守架匹配，不能只看人物总高。

防止非预期漂移不等于冻结所有躯干/骨盆地标。重踢、飞踢、投掷等必须有准备承重、髋部驱动、上体反向平衡与回收；锁相机、解剖体积、肢段长度和实际支撑接触，允许意图明确的重心轨迹。单脚长时间悬腿但头肩髋全冻结，即使RGBA清晰、脚位稳定也不能靠缩小验收范围当作高质量重踢通过。

打包检查必须验证同一单动作manifest顶层frames/sheet/contactSheet/video与clips[0]引用一致（路径前缀归一后比较）。联系表显示新稿、clips.frames仍指旧RIFE会造成修复假象。实际页面抽查帧图src与新文件SHA，而不只确认下载链接存在；缺失四源单张预览也要补齐。

疾跑门禁必须追踪同一条腿的髋/裤口/大腿连接与遮挡身份跨完整周期：前支撑→髋下经过/后蹬→后屈→前抬→同脚落地，另一腿反相。第1与第7、第4与第10若仍是相同裤腿分支在前，即使摆臂已换相、腿有明暗差也判同脚循环失败。近远肢体身份不能靠画面左右位置或调色命名；四源先用裤口覆盖关系证明交换，再独立验中间经过和首末闭合。用户指出漏检后须撤销旧通过与当前下载包状态，保留原验收记录，不只另写一个失败备注。
