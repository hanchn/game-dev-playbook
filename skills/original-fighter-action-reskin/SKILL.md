将原作动作保留为可追溯的 source image → target image 对应。角色形象可变，原作实际帧序、重复持帧、偏移、朝向和时间基准分别记录。沿用当前项目已有UI；每张完成提取与检查即接入，不等待整个角色齐套。

## 出图与接入

- 先读取项目当前角色定稿及用户映射。不同目标角色是否用不同源角色由项目要求决定；不要把示例映射泛化为已确认。当前人物未覆盖所有动作时不得宣称全套完成。
- 区分原游戏运行采样、MUGEN/AIR改编和新生成美术。取得实际源刷新率；独立姿势图数、序列定位元素数、源tick数、录屏fps是不同指标。
- 清点原图并跨动作去重：原作几张独立图就对应几张目标图。相同原图可在不同动作复用，但每段持帧和pivot变化须保留。不要强制四关键帧或十二帧，不用重复图冒充新姿势。
- 内置 imagegen：角色定稿/样式图作身份参考，原角色姿势总图作姿势参考。提示明确真实所需数量、逐图顺序、转身/背面与近远肢归属、同一物理比例、完整手脚与透明留边。先传原作全身姿势参考、再传目标身份参考。不要给含其他攻击动作的条带当“仅格式参考”：模型曾照抄其重拳并覆盖待机来源。读[已验证提示模板与失败](references/production-lessons.md)。
- 全身对标包括髋、膝、踝、足与支撑变化；源脚固定时不得生成全身摆动，源腿移动时不得锁死下半身。技术底边对齐不能替代逐腿姿势检查。
- 横向单排条带是本次试验有效方案，不是普遍模型保证。原始RGB预览曾看似黑黄光晕，后经白底alpha合成证明背景干净；每次必须检查实际alpha及深浅底合成，不能凭RGB预览或最大alpha254判失败。失败结果留档，不因提示写了透明便认定通过。生成失败/不可用不静默改用收费API，明确拒绝的请求停止。
- 提取图集只做像素归属分离、裁切、补透明边；保留所属原始RGBA与哈希，不用旋转、拉伸、程序绘画或补帧伪造新美术。禁止凭等分格或相邻bbox中线直接切：踢腿与邻帧肩部可在X范围重叠。对无接触单排使用 [sprite_strip_extract.py](scripts/sprite_strip_extract.py) 的真实alpha归属。输入应是每个全身轮廓连通的条带；触碰合并、独立武器/配件或额外大组件须另审并显式标注，不猜帧数。
- 原点依据对应原帧和角色地标注册；固定每生产组的比例，回放重施源pivot差及实体/镜头位移。匹配每个对应帧的水平高度与原作跳跃位移，不能把全部帧脚底贴地或逐帧自动fit。注册高度通过不证明全部关节姿势已一比一。
- 每张检查通过即接入自身源帧槽，尚缺帧明确显示待接入；不代播其他招式。记录revision/不可变资源，运行页及时加载新数据。不要每个tick重复设置同一DOM图片URL导致动画抖动或多余网络请求。

- 双脚注册必须跟踪对应接触点：最低若干像素的全局中点会在单脚/双脚之间切换，造成源脚未动而目标横跳。分别测量左右脚；支撑脚连续对应，另一脚单独报告水平与垂直残差。等底边、固定整体中心或支撑脚误差为零都不能证明姿势正确；站距、抬脚画错须修原图。
- 并行写同一 dataset 时指定唯一集成者；其他生产者交付按动作或帧槽的补丁。合并前重读最新数据，复用图按最新 pivot/比例重绑定，并使用字节哈希冲突检测、文件锁与原子替换；不得把旧整份 JSON 覆盖回去。

## 验收与知识记录

- 逐定位元素检查源图身份、时长、pivot差、朝向和对应底边坐标。检查实际alpha连通归属，确保无相邻姿势残片并保留完整指趾；来源像素身份验证与美术观感分别记录。
- 在实际引擎检查每动作全部图，正常/慢放/逐tick/镜像/切换；记录加载失败、可见性、墙钟推进和真正渲染fps。保留同姿势同倍率的失败/修复截图和短录屏。
- Sprite图、视觉近似、动作状态机、命中/受击/格挡框、取消窗口与命中停顿分别验收。按键尝试名不证明动作成功；护架姿势不证明实际挡住攻击。
- 已完成仅代表已验证范围。13段观察窗口的完整映射不等于源角色全部招式。姿势候选、技术接入、用户美术接受分开记。
- 提交已验证批次和可复现脚本，保留源收据、提示、哈希和失败根因。共享技术经验时不捆绑私有角色图、ROM、凭据或机器绝对路径。脚本依赖 Python、Pillow、NumPy。

批量用户授权时可按角色隔离并行生产：每个生产者只写分配角色的原图、提示和dataset；共享运行页、索引和发布由单一集成者处理。逐图数量错误、姿势抄错、腿部动作缺失直接保留失败并修复；并行速度不能代替源姿势核对。
