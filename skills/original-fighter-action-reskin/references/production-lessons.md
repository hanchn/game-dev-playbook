# 已验证经验与适用范围

此流程验证过一个格斗角色13段观察窗口、60张原图与60张对应新图、387个定位/持帧元素。刷新率由原机实测，不能写成通用60Hz。独立绘图去重后跨动作复用；窗口包含动作前后待机，窗口图数不能叫招式本体帧数。碰撞、状态和取消不在这些图像证据中。

## 有效出图模板

参考顺序优先原作全身姿势，再用目标角色定稿身份。不要额外传含其他动作的条带作“仅格式”：舰队中多个角色待机被错误画成重拳，证明文字限定不能保证参考用途隔离。源姿势参考单列角色图与原生pivot。提示例如：

> Source image1 provides whole-body poses, image2 provides target identity. Draw EXACTLY N corresponding poses in reading order, ONE horizontal row, generous transparent gutters. Preserve character identity and one physical scale. Copy torso rotation, back/front visibility, limb ownership, planted foot and knee/elbow bend. Keep all fingers/toes visible. Alpha-zero empty background, opaque figure interiors. No glow, floor, shadow, labels, text, grid or extra poses.

N必须来自实际源图清单；本例不是四帧模板。全身不可触碰的单排可采用附带脚本拆分；生成数量、独立大组件数量和真正动作图数必须一致。

## 真实失败：邻帧混入

长腿侧踢/宽站姿和邻帧肩肘在X方向交叠，人物彼此并未接触。按相邻bbox的中点作垂直裁切会同时裁掉本帧脚尖、留下隔壁肩部碎片。动画时序测试和底边坐标全通过仍会漏掉。

修复：从实际alpha大组件确定人物种子，沿实际非零alpha扩展每个归属，逐归属原像素提取并补边。仅保留自己归属的RGBA，不用bbox、凸包或膨胀去补缝。对比同一帧的隔离PNG和引擎截图，验证本体原像素未变且相邻碎片已消失。共用修复对其他条带复查。

脚本对不连通配件和相触轮廓有显式限制，遇到数量不符应停止和审图，不自动拿最大N个轮廓冒充通过。无接触单排只是一种输入布局，不覆盖任意多行atlas。

## 复核推翻：不能凭RGB预览判透明失败

曾将多行原图在预览中的黑/黄光晕及最大alpha254误判为透明失败，造成不必要重生成。随后检查原始RGBA、采样alpha以及白底真实合成，证明背景大多alpha0，人物视觉完整干净；零alpha中的RGB并不应显示。最大alpha254也接近不透明，不能据此定背景不合格。旧图保留原名，但其“背景失败”标签已撤销，布局是否越格另审。

标准改为检查真实深/浅底合成、角色内部视觉、轮廓和对应像素alpha。仅真实可见的背景污染才判失败；不要因查看器忽略alpha而反复重绘。横向条带的好处是便于归属提取，不保证生成结果，也不意味着多行必然不能透明。

## 坐标

保留原作实体/镜头相对移动、原图尺寸、裁切pivot及重复元素offset。目标角色每组共用比例，按脚部对应地标注册；底边高度只是一个检查轴，肩、拳、膝和躯干旋转仍需看图。画布透明留边不应当作可见人物包络。

## 后续验证推翻的格式参考假设

首批透明攻击条带作为格式参考成功，但后续批量待机频繁误抄其攻击动作。现将源姿势第一、身份第二，移除不相关动作参考；透明格式用文字描述和真实alpha检查保证。此修正要覆盖先前较乐观的“透明条带可通用作格式参考”判断。

## 全身与并行

用户指出上半身看似对应，但袋鼠遗漏源腿偏移、牛头人固定支撑腿却全身晃动。需单独对比左右髋膝踝与足、支撑固定区和实际移动区；数据底边坐标相等不能证明姿态正确。源只一张静图就只做一张，不添加假呼吸。

舰队按角色隔离写目录，同时生图并逐组接入；集成者统一索引和运行测试。批量发现误攻击、抬腿夸张、错手掌、图数多出等失败时保留并定向修复，禁止仅因图集数量足够而完成。
